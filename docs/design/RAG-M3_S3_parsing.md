## 2. Dependency decisions (owner Q5: only if genuinely required)

### 2.1 markdown-it-py 4.3.0: added (exact pin, plus `mdurl` 0.1.2 transitively)

The constructs that make a hand-written line parser unsafe, all measured:
- **885 heading-like lines inside code fences** (146 files), for example `# comment` in shell or Python. A naive splitter would cut code there.
- **236 fences inside list items** (72 files). Their closing fence is indented, so a fence matcher must track list containers.
- **671 files with HTML blocks** and **884 files with pipe tables**, which interact with CommonMark's HTML-block and table rules.
- Setext and indented code blocks exist (4 indented code blocks), and they need CommonMark's precedence rules.

markdown-it-py is a CommonMark-compliant tokenizer with a built-in table rule. Its behaviour on each of these constructs is covered by tests (`tests/unit/corpus/test_parse.py`):
- heading-like lines inside code;
- tilde and indented code;
- fences inside lists;
- nested lists;
- tables with escaped pipes;
- HTML blocks;
- `<details markdown='1'>`;
- comment-led list items.

### 2.2 PyYAML: **not added**

[MEASURED] in front matter across all 2,031 pages:
- every page has front matter, with exactly one top-level `title:` line;
- **2,011 plain** titles and **20 single-quoted** titles;
- no double quotes, escapes, block scalars, or plain values containing `: ` or ` #`.

A strict extractor handles exactly these forms, including YAML's `''` escape in single-quoted strings. **Every other form produces a recorded `front_matter_title_unsupported` warning and `title = None`; nothing is guessed.** Other keys (`redirect_from`, `railroad`, …) are not needed.

PyYAML would add a dependency to parse data the corpus doesn't use. Tests: `test_liquid_frontmatter.py` (9 front-matter tests, including the four 1.2-era stubs whose closing `---` ends the file without a newline).

## 3. Parsing rules

### 3.1 Pipeline (per page; the source bytes are never modified)
1. **Decode** as UTF-8. Invalid bytes give a warning, never a crash.
2. **Strict front matter:** `title` only (§2.2).
3. **Liquid pass** over the whole body (Jekyll evaluates Liquid before Markdown, including inside code). **Line numbers are preserved:** suppressed text is replaced by its newlines.
4. **Extraction:**
   - Sphinx reference pages go to the HTML extractor;
   - all other pages go to markdown-it, with HTML blocks classified one by one.
5. **Page kind:**
   - `landing` if listed in `configs/parsing.toml` (with a reason);
   - `empty` if no content block remains;
   - otherwise `content`.

   Excluded pages are still fully parsed and kept in the output.

Every block carries its source line range. Every applied rule is recorded as a transformation (rule, line, detail); every problem is recorded as a warning.

### 3.2 Liquid
- **Site variables** (Q6): `{{ site.X }}` becomes `[site:X]`.
  - `{% include install/latest_client.html client="c" %}` is removed, and the `latest_version` / `latest_package` / `latest_release` it assigns become `[site:latest_version:c]` etc.
  - **Markers contain no spaces.** A marker inside a link URL therefore keeps the link valid; the first implementation used `client=c` with a space, which broke 22 links, and was fixed.
  - The renderer never reads site data, so no current-release number can be introduced. This is tested.
- **`{% raw %}`:** tags removed, content verbatim and uninterpreted (7 blocks, including Go `{{Name: …}}`).
- **Links:**
  - `{% link docs/X/p.md %}` becomes `https://duckdb.org/docs/X/p.html` (10,074);
  - `{% post_url 2021-12-03-duck-arrow %}` becomes `https://duckdb.org/2021/12/03/duck-arrow.html` (367).

  Link *targets* are not content; only link text enters block text.
- **Includes:** see §5.
- **Conditionals:** provisional rule (§7).
- **Loops:** `{% for %}` bodies iterate over site data and cannot be evaluated, so they are removed and recorded (1 occurrence, on an excluded generated page).
- **Aliases:** `{% assign x = latest_* %}` becomes an alias (1 occurrence). Other `assign`/`capture`/`case` tags give a warning.

### 3.3 Markdown
- **Headings** keep their level (H1 2, H2 7,016, H3 5,409, **H4 10,581, H5 13,359**) and their source line.
- **Paragraphs:**
  - soft line breaks become spaces, and `<br>` / hard breaks become newlines;
  - emphasis markers are dropped, but text is kept;
  - code spans are kept with backticks;
  - images become `[image: alt]`.
- **Code** (fenced 20,546; indented 4): kept verbatim with the language tag. Nothing inside code is changed.
- **Tables** (6,252 = 3,282 GFM + 2,970 reconstructed Kramdown) are normalised to `| … |` rows, with a delimiter after the header rows when there is a header.
  - Kramdown reconstruction (C11): a paragraph whose source lines **all** start with `|` becomes a table. A delimiter row, if present, marks the header. Cells are split on pipes outside code spans, so `'a' || 'b'` stays in one cell. `meta.source = kramdown_pipe_rows` and `meta.header` record the origin. No row is invented.
  - Cell text is rendered inline, and `|` inside a cell is escaped.
  - `rows` and `columns` are recorded.
  - Q3's row-splitting is S4's job; S3 only measured that **no single table row exceeds 512 approximate tokens**.
- **Lists** (5,956) are rendered as indented text, with numbering and nested code fences kept verbatim.
- **Blockquotes** (1,725) are kept as text. A callout kind is recorded when the first word is one of Warning (541), Deprecated (178), Tip (125), New (104), Bestpractice (72), Note (34) or Installation (24).
- **Kramdown attributes** `{:.class}` / `{: #id}` are removed outside code (705); full-line attribute paragraphs are dropped.
- **Inline HTML:** comments removed, `<br>` becomes a newline, other tags stripped with text kept (2,194 tags stripped).
- **Malformed links:** a link markdown-it cannot parse because the source is malformed is **kept as written and warned** (`markdown_link_unparsed`). There are 2 occurrences, an upstream typo (missing `)`) in 1.2/1.3 `aws.md`.
- **Upstream typos are never silently repaired.** The only tolerance applied is Kramdown's own: a table row may omit its trailing `|`, and 3 rows in `aggregates.md` (1.2–1.4) do.

### 3.4 HTML blocks inside Markdown pages (stdlib `html.parser`)

| Classification | Count | Handling |
|---|---|---|
| comment only | 604 | Dropped (recorded) |
| wrapper only (`<div class="nostroke_table">`, `</div>`, anchors) | 7,832 | Dropped (recorded) |
| empty railroad-diagram container `<div id="rrdiagram">` | 205 | Dropped (recorded). The diagram is drawn by JavaScript from data outside the docs, so no text exists to keep |
| pre-rendered highlighted code (`<pre>`) | 3,142 | Code block, text verbatim, language from `language-*` class, entities decoded |
| landing-page link boxes (`box-link`) | 22 | Navigation block of the visible labels (labels sit in sibling `<span>`s in 1.2–1.5) |
| anything else | 27 | `html_text` block of its visible text, warned `html_block_generic_text` (Node.js `<dl>` reference, marimo `<div>`s, `<details>` summaries) |

Further rules:
- **Containers split across blocks:** containers (`div`, `details`, `section`) legitimately open in one CommonMark HTML block and close in another (Kramdown `markdown='1'`), so their balance isn't flagged. Unbalanced *content* tags inside one block are warned, and their text is kept.
- **Comment-led blocks (C9):** an HTML block beginning with a comment followed by Markdown has the comment removed and the rest re-parsed as Markdown.

### 3.5 Generated Sphinx API reference (5 pages, Python client)

**Routing:** body starts with `<div class="documentwrapper">`.

Each `<dt>` in a `<dl class="py …">` becomes an **API entry**:
- `api_id` = the `dt` id;
- `signature` = visible signature text, with ¶ permalinks removed;
- `level` = API nesting depth (1 for classes and functions, 2 for methods);
- the entry text = the matching `<dd>` text.

Further rules:
- **Nesting:** nested API lists become child entries and are **not** copied into the parent's text.
- **Docstring field lists:** `<dl class="simple">` (`Parameters:` / `Returns:`) stay as text.
- **Code:** `<pre>` is kept verbatim inside a ``` fence. A test caught and fixed indentation being collapsed here.
- **Headings:** `<h2>` in `<section>` (2.0 only) become headings.
- **Robustness:**
  - text outside any entry is kept as `html_text` and warned;
  - unclosed entries are emitted and warned;
  - nothing raises.

[MEASURED] For all five pages, API entries = `<dt class="sig sig-object py" …>` signatures (1.2: 364, 1.3: 358, 1.4: 371, 1.5: 381, 2.0: 647). 14 real property entries in 1.4/1.5 have no `id` attribute (for example `CSVLineTerminator.name -> str`). They are kept with an empty `api_id` and warned `api_dt_without_id`; no id is invented.

## 7. S3-D1: conditionals with a hard-coded `{% else %}` fallback (decided: option B, see §10.1)

**Evidence.** All 35 conditionals have this shape, in 1.4/1.5 client pages and the 1.5 clients table:
```
{% if site.maintained_duckdb_version != "" %}[{{ site.maintained_duckdb_version }}](…?version=current…)
{% else %}[1.4.5](…?version=stable…){% endif %}
```
At the pinned commit, Jekyll renders the **if** branch (the variable is "1.5.6"). The **else** branch is the author's static fallback, a 1.4.x version written into the page. Neither branch is a reliable statement about the archived version.

**Alternatives:**

| | Rule | Output for the example | Trade-off |
|---|---|---|---|
| **A (provisional, implemented)** | Keep the if-branch (with neutral markers); drop the else-branch, recording it verbatim | `[site:maintained_duckdb_version]` | No contradictory values; the fallback text is preserved in the transformation log, not in content |
| B | Keep both, labelled | `[site:maintained_duckdb_version] (fallback in source: 1.4.5)` | No text dropped, but injects a hard-coded 1.4.x number into 1.5 pages, a version-confusion risk |
| C | Replace the whole conditional with one marker | `[site:conditional maintained_duckdb_version]` | Simplest; loses the link text structure |
| D | Keep only the else-branch | `1.4.5` | Matches what a site without the variable would show, but puts a specific, possibly wrong, version into content |

My recommendation was A. **The owner chose B** (2026-11-21): both branches are preserved and labelled. A is no longer implemented. The implementation is in §10.1.

## 10. S3b extension (owner decisions, 2026-11-21)

### 10.1 S3-D1 = option B: both branches kept and labelled

Every `{% if C %}A{% else %}B{% endif %}` (all 35 in the corpus) is rendered as:

```
[liquid-if: C] A [liquid-else: fallback written in source, hard-coded version 1.4.5] B [liquid-endif]
```

1. **The conditional branch** `A` is kept, with site values as neutral markers (`[site:…]`). Current site values are never rendered.
2. **The fallback branch** `B` is kept exactly as written; only the normal rules apply inside it (for example, `{% link %}` resolves to its URL).
3. **Both are labelled** with the original condition (`C`) and the branch type (`liquid-if` / `liquid-else` / `liquid-endif`; `liquid-unless` for `unless`).
4. **The fallback label names every hard-coded `x.y.z` version it contains.** All 35 fallbacks contain one (`1.4.3`, `1.4.4`, `1.4.5` or `1.4.5.0`). A fallback without a version is labelled `fallback written in source`.
5. **Neither branch is treated as authoritative.** The labels make the alternative explicit, and blocks containing them carry `meta.liquid_branches = true` so S4 can identify them.
6. **The transformation record** (`liquid_if_else_both_kept`) stores the condition, the **raw source of both branches** and the hard-coded versions, with the source line.
7. **Layout safety:** labels never contain a newline, so line numbers are kept. A `|` in a condition is escaped, so table cells don't split.
8. **Conditionals inside a Markdown link URL** (4 cases, in the 1.5 ODBC pages): the readable labels contain spaces, which would break the link and leak raw Markdown into the content. A test found this. There, the labels are written without spaces (`[liquid-if:site.x-!=-""]…[liquid-else:fallback-written-in-source,hard-coded-version-1.4.5.0]1.4.5.0[liquid-endif]`), so the link stays valid.

   As with every link, the URL isn't block content, so these four are preserved in the transformation record (`liquid_if_in_link_url` plus `liquid_if_else_both_kept`), not in block text. Inside code blocks the conditional is kept verbatim with readable labels.

A conditional without `{% else %}` becomes `[liquid-if: C] A [liquid-endif]`; none occurs in the corpus.

Tests (`test_liquid_frontmatter.py`, `test_parse.py`, `test_real_parsing.py`) cover:
- both branches surviving parsing, including in a table cell;
- the labels and their distinguishability;
- the recorded raw source of both branches and the version;
- no current site values;
- multi-line branches;
- `unless` and `|` in a condition;
- conditionals in link URLs;
- conditionals nested inside an unevaluable loop;
- on the real corpus: 35 kept = 31 visible in blocks + 4 in link URLs.

**Naming and format:**
- Parts are named by docs series, the convention used throughout the repository (`docs/1.4/`, `version` fields, report columns). Each index entry also records the behaviour package.
- One `FileRecord` per line, with unchanged fields (`version`, `path`, `git_blob`, `sha256`, `bytes`, `words`), sorted keys and records sorted by path. LF line endings, final newline.
- `excluded_files` stays in the main file, which differs from my earlier proposal. It is small, and the brief moves only the documentation file records.

**Integrity checks.** The strict reader (`read_manifest`) and `vrag corpus verify` report all of these. `manifest --check` additionally compares every part byte for byte with a fresh build.
- **Missing part.**
- **Modified part:** the sha256 differs from the index.
- **Unexpected file** in `files/`.
- **Duplicate record**, within a part or across parts.
- **Inconsistent version:** the record's version or path prefix differs from its part.
- **Unsorted records.**
- **Record count mismatch:** against the index, and against the version's `md_files`.
- **Content mismatch:** the records must reproduce the version's `content_hash` and word count. This catches an edit even when the index hash is updated to match.
- **Index gaps** and paths that break the naming convention.
